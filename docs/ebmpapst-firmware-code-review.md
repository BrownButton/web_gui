# EC FAN ebm-papst 기능 코드 리뷰 결과

- 작성일: 2026-10-15
- 대상: ec-fan 저장소의 `ebm/*` 브랜치 16개(기준 커밋 `18b625e`)
- 방법: 브랜치마다 리뷰어 1명이 변경 코드를 끝까지 따라 읽고, 필요하면 순수 로직을 PC에서 컴파일해 시험했습니다. 브랜치 사이의 병합 문제는 별도 리뷰어가 확인했습니다. 실보드 시험은 하지 않았습니다.
- 관련 문서: `ebmpapst-firmware-modbus-test-plan.md`(시험 절차서)

## 1. 판정 기준

| 항목 | 기준 |
|---|---|
| 심각도 높음 | 모터 오동작, 안전, 멈춤이나 리셋, 데이터 손상, EEPROM 수명 소진 |
| 심각도 중간 | 레지스터 값 오류, 사용자에게 영향이 있는 스펙 위반, 문서에 없는 기존 동작 변경 |
| 심각도 낮음 | 경계 조건, 작은 스펙 차이 |
| 확인됨 | 코드 경로를 끝까지 추적했거나 PC 시험으로 재현함 |
| 가능성 | 경로는 추적했지만 발생 여부가 하드웨어나 타이밍에 달림 |

기준 펌웨어에 원래 있던 결함(D 영역 다중 레지스터 주소 계산, D012 비트 순서, D001 되쓰기 등)은 브랜치가 악화시킨 경우만 적었습니다.

## 2. 요약

**결론**: 16개 브랜치 모두 Main 빌드는 오류 없이 되고 기능 골격도 의도대로 들어갔습니다. 하지만 지금 상태로 병합하거나 출하할 수는 없습니다. 보드 리셋(HardFault), 정지 지령 무시, EEPROM 수명 소진, 설정 유실로 이어지는 결함이 브랜치 단독 기준 10건(공통 원인 1건 포함), 병합 기준 7건 있습니다. 코드는 수정하지 않았고, 아래는 리뷰 결과만 정리한 것입니다.

**현재 작업 브랜치(`feature/ecfan-600w-1phase-pfc`)와의 충돌**

- PFC 커밋 `37920b6`은 Input register **D053**을 "AC input voltage peak"(`ebm04.ac_input_voltage_peak`)로 추가했습니다. `ebm/overmod-limit-warning`은 같은 D053을 "Limit status"(`ebm04.limit_status`)로 씁니다. 둘 다 병합하면 오브젝트 사전 인덱스가 중복되어 5절 6번처럼 그 뒤의 Input register가 빠질 수 있습니다. 둘 중 하나를 다른 주소로 옮겨야 합니다. PFC 쪽의 D03D(Line voltage)는 다른 브랜치와 겹치지 않습니다.
- 두 브랜치 모두 `Common/ecfan_memory_map.h`의 `inverter_boot_version` 바로 뒤에 16비트 필드 하나(`ac_input_voltage`, `limit_status`)를 추가합니다. 텍스트 충돌이므로 둘 다 남기면 됩니다. Main과 Inverter가 같은 헤더를 쓰므로 두 펌웨어를 함께 다시 빌드해야 합니다.

**권장 조치 순서**

1. **보드 리셋과 설정 유실부터 막습니다.** 공장·고객 설정의 FC03 HardFault(3절 1번)를 고칩니다. `cia402appl.h:1067`에 `#pragma pack( pop )`을 넣고 `ebmpapst_param.h`에 정적 검사를 넣습니다(4절). pack 수정은 기준 브랜치(main)에 먼저 넣고 다른 브랜치를 그 위로 다시 올리는 것이 가장 간단합니다.
2. **운전 안전 결함을 고칩니다.** Fail-safe 1, 2번, I/O 1번, Shedding의 D106 전환(5절 1번)이 해당합니다.
3. **EEPROM 수명과 데이터 결함을 고칩니다.** 파라미터 세트 1번, 모니터링 1번, 파워 리미터 1번, 마스크아웃 1번이 해당합니다.
4. **병합 규칙을 정한 뒤 병합합니다.** 5절의 `update_local_map()` 형태, D001 되쓰기 조건, `modbus_server.c` 분기 순서, TIM6 호출 순서를 따릅니다. 병합 후에는 오브젝트 사전 인덱스 중복을 검사하고, IAR 스택 분석을 돌리고, 스택을 2 KB로 늘립니다.
5. **PFC 브랜치와의 D053 충돌을 정리합니다.** 병합 전에 둘 중 하나의 주소를 바꿉니다.
6. **중간, 낮음 항목을 처리합니다.** 사용자에게 보이는 레지스터 값 오류(제한값 5건, 릴레이 3건 등)부터 처리합니다. 고치지 않는 항목은 시험 절차서에 알려진 제약으로 적습니다.
7. **실보드 시험을 합니다.** `ebmpapst-firmware-modbus-test-plan.md` 절차를 따릅니다. 이 리뷰에서 "가능성"으로 판정한 항목(스택, 경쟁 조건, 부팅 구간 EEPROM 접근)도 이때 함께 확인합니다.

## 3. 브랜치별 결과

### ebm/D15B-D15F_fail-safe

**요약**: 감시 선로, 해제 조건, 값 검사, EEPROM 블록은 대체로 의도대로 구현됐습니다. 다만 RS485 경로의 D001 복원과 32비트 경과 시간 계산에서 운전에 영향을 주는 결함 2건이 있습니다. 높음 2건, 중간 1건, 낮음 2건입니다.

| # | 심각도 | 위치 | 문제 | 발생 시나리오 | 수정 방향 | 판정 |

**확인했지만 문제없던 부분**

- 32비트 타임스탬프는 정렬된 변수라 원자적으로 읽고 씁니다. TIM6 실행 중에는 SysTick이 멈춰 있어 순서가 뒤바뀌지 않습니다(문제는 2번의 랩어라운드뿐입니다).
- 감시 타이머는 CRC가 맞고, 자기 주소나 브로드캐스트로 온 프레임만 갱신합니다. USB 프레임은 제외합니다.
- 범위 밖 값은 마지막 유효값으로 되돌리고, 배열 범위를 벗어나는 접근은 없습니다.
- EEPROM 블록 0x0700은 12바이트이고 페이지 경계를 넘지 않습니다. 부팅 시 접근은 TIM14를 막고 합니다.
- 오브젝트 순서와 메모리 순서가 일치하고, float D160의 정렬이 유지됩니다.
- 해제 히스테리시스와 500 ms 유지 판정, PWM 신호 없음 판정은 의도대로 동작합니다.

### ebm/D103-D10D_D12A-D13F_parameter-set-sensor-control

**요약**: PI 연산, 입력 특성곡선, 구조체 배치, D106 미러링 보류 로직은 정상입니다. 결함은 높음 1건(D103 = 1에서 D001이 바뀔 때마다 EEPROM 쓰기), 중간 2건, 낮음 3건입니다.

- 운전 차단은 D000 Error와 전원 재투입으로 풀립니다. D000 Reset 시 Inverter도 함께 리셋되어 플래시 보정값으로 복원됩니다.

- D1F7 저장은 값이 바뀔 때만 190 V 조건 아래 한 페이지 안에서 합니다. 오브젝트 순서와 메모리 순서가 맞습니다.

## 4. 공통 결함: `ebm03` 구조체 배치 불일치

**결론**: 6개 브랜치에서 `ebm03`(Holding register 구조체)의 D160 이후 필드 위치가 소스 파일마다 2바이트씩 다릅니다. 같은 변수를 파일마다 다른 위치로 읽고 쓰므로, D1FF(종단 저항) 설정이 재부팅 후 사라지고 다른 RAM을 덮어쓰는 등 동작이 틀어집니다. 병합 전에 반드시 고쳐야 합니다.

**원인**

1. `ECFAN-Main/EtherCAT/Inc/cia402appl.h:996`의 `#pragma pack( push, 2 )`에 짝이 되는 `pop`이 없고, 조건부 구간 밖에 있습니다. 그래서 이 줄 뒤에 나오는 모든 구조체가 2바이트 정렬이 됩니다.
2. `cia402appl.h`를 `ebmpapst_param.h`보다 먼저 include하는 파일(`ebmpapst_param.c`, `coeappl.c`)은 `ebm03`을 2바이트 정렬로 봅니다. 나머지 파일(오브젝트 사전이 있는 `cia402appl.c`, `ecfan_memory_main.c`, `modbus_server.c`, 새 `ebm_*.c` 모듈)은 기본 정렬로 봅니다.
3. 기본 정렬에서는 float(D160) 앞의 16비트 필드 수가 홀수이면 float 앞에 2바이트 패딩이 들어갑니다. 2바이트 정렬에서는 패딩이 없습니다. 따라서 필드 수가 홀수이면 두 배치가 달라집니다.
4. 기준 펌웨어는 float 앞 필드가 20개(짝수)라 두 배치가 같아 드러나지 않았습니다.

**브랜치별 float(D160) 앞 16비트 필드 수**

| 브랜치 | 필드 수 | 판정 |
|---|---|---|
| 기준 `18b625e` | 20 | 정상 |
| `ebm/D002-D004_password-access` | 23 | **불일치** |
| `ebm/D009-D03D_D180-D1A1_monitoring-error-history` | 23 | **불일치** |
| `ebm/D00C_D1A2-D1AA_serial-addressing` | 21 | **불일치** |

| `ebm/D153_D620-D624_relay-output` | 21 | **불일치** |
| 나머지 10개 브랜치 | 짝수 | 정상(파라미터 세트 브랜치는 패딩 필드와 정적 검사를 두었음) |

**증상**

- `ebmpapst_param.c`가 다루는 D1FF(종단 저항 기본값 쓰기, EEPROM 로드, 저장에 쓰는 getter)와 D160, D162가 오브젝트 사전과 다른 위치를 봅니다. 비밀번호 브랜치를 IAR로 컴파일해 확인한 위치는 `ebmpapst_param.c` 기준 46, 50, 54바이트, 오브젝트 사전 기준 48, 52, 56바이트입니다.
- 웹 GUI가 D1FF ← 1을 쓰면 오브젝트 사전은 `ebm03` 바깥(56바이트 위치)에 씁니다. 종단 저항은 즉시 켜지지만, EEPROM에는 다른 위치의 값이 저장되어 재부팅하면 설정이 사라집니다.
- 브랜치가 D160 뒤에 추가한 필드(릴레이 D620~D624, 시리얼 D1A2~D1AA, 모니터링 D180~D1A1)도 파일마다 위치가 다릅니다.
- 기준 펌웨어에서 동작하던 D15F~D163 다중 읽기도 실패합니다.

**수정 방향**

1. `cia402appl.h`의 packed 구조체 정의 뒤에 `#pragma pack( pop )`을 넣습니다. 그 전에 이 누수에 기대는 다른 구조체가 없는지 확인합니다.
2. `ebmpapst_param.h`에 `_Static_assert( offsetof( EBMPAPST_FC03_HOLDING_REGISTER, min_sensor_value_address ) % 4 == 0, ... )`를 넣어 빌드 단계에서 막습니다.
3. 브랜치를 병합할 때마다 합친 필드 수의 홀짝이 바뀌므로, 필요하면 예약 필드를 하나 넣어 짝수로 맞춥니다.

**병합 후 `update_local_map()`의 형태**

같은 줄을 브랜치마다 다르게 고친 곳은 아래 형태로 합쳐야 위 2번, 3번 결함이 생기지 않습니다. 파워 리미터 브랜치가 `calculate_temperature_derating()`을 삭제하므로 다른 브랜치 줄에 남아 있으면 링크 오류가 납니다.

```c
uint16_t src = ebm_io_select_set_value_source();            // 1단계 (D028 기록)
uint16_t cmd = /* switch(src) 원래 값 */; const uint16_t raw_cmd = cmd;
cmd = ebm_failsafe_update(src, cmd);                        // 2단계
const uint8_t fs = ebm_failsafe_is_active();
cmd = ebm_paramset_process_set_value(cmd, fs ? 255u : src); // 3단계
cmd = ebm_limits_apply(cmd); const uint16_t lim = cmd;      // 4단계
cmd = ebm_maskout_apply(cmd);                               // 5단계
cmd = ebm_power_limit(cmd);                                 // 6단계
cmd = ebm_io_apply_enable_direction(cmd);                   // 7단계
update_setpoint(cmd);
if (src == RS485 && !fs && !ebm_paramset_sensor_control_active() && raw_cmd != 0 && lim == 0) ebm03.setpoint = 0;
ebm_shedding_process(); ebm_rotorcal_process();             // 캘리브레이션이 마지막
```

**다른 공유 지점의 병합 규칙**

- `update_ebmpapst_parameter()`: D028 블록은 I/O 쪽을 택해 삭제하고, D106 반영에는 파라미터 세트 보류 조건과 1번의 Shedding, 캘리브레이션 조건을 함께 둡니다.
- `UpdateParameterChange()`: 모니터링과 마스크아웃의 쓰기 알림을 맨 앞에 둘 다 둡니다. D137, D138, D13B, D12F는 파워 리미터 버전을 택합니다. D000 처리에는 Shedding과 캘리브레이션의 Error 처리, 설정의 Param 처리를 모두 넣습니다.
- `WrtieParameterToEEPROM()`: 전압 검사 뒤에 설정, 마스크아웃, 파워 리미터의 저장 호출을 모두 둡니다.
- `modbus_server.c`: FC03은 12번 순서를 따릅니다. FC06, FC10에는 비밀번호 검사와 주소 매핑의 레지스터별 권한 검사가 이중으로 걸리지만 결과가 같아 문제없습니다. FC 0x2B에는 비밀번호 검사가 필요합니다.
- `stm32g0xx_it.c` TIM6 순서: `update_ebmpapst_parameter(); update_local_map(); ebm_sn_task(); ebm_relay_update();`(릴레이가 마지막)

**병합 후 D011, D012 쓰기 순서(TIM6 한 주기)**: 알람 재구성, Inverter 경고 복사, 모니터링(n_Low), I/O(진단 출력이 읽음), Fail-safe(OpenCir), 파워 리미터(P_Limit), Shedding(BLK, LRF), 캘리브레이션(RL_Cal), 릴레이(지연과 마스크 후 재기록) 순서입니다. 같은 비트를 다른 의미로 쓰는 경우는 없습니다.

**확인했지만 문제없던 부분**

- 약한 함수 계약 11쌍의 시그니처, 반환형, 단위가 모두 같고 링크 오류가 없습니다(기본값 차이 13번, 정의 없음 18번 제외).
- 브랜치별로 추가한 오브젝트 사전 인덱스와 전역 심볼이 서로 겹치지 않습니다.
- EEPROM 블록 14개가 서로, 그리고 기존 영역과 겹치지 않습니다. TIM6에서 EEPROM을 쓰는 곳은 없습니다(부팅 구간 예외 15번).
- 병합 후 Main 플래시는 약 83.8 KB로 앱 영역 112 KB의 약 73 %입니다. Inverter 증가는 약 0.3 KB입니다.
- 비밀번호 권한 표와 설정의 고객 비트맵이 서로 일치하고, D012 raw 마스크가 순서 수정 브랜치와 일치합니다.
- Inverter `modbus.c`(캘리브레이션 + 과변조) 병합에 충돌이 없습니다.
