# EC FAN ebm-papst 기능 Modbus 시험 절차서

- 작성일: 2026-10-14
- 대상 펌웨어: ec-fan 저장소의 `ebm/*` 브랜치 16개. 기준 커밋은 `18b625e`(main)입니다.
- 근거 자료: `docs/Customer version of MODBUS series parameter specification V6.3.pdf`, `docs/ebmpapst-feature-development-plan.md`, 각 브랜치의 소스 코드

## 1. 개요

이 문서는 ebm-papst MODBUS V6.3 스펙에 맞춰 새로 구현한 펌웨어 기능을 Modbus RTU로 검증하는 절차를 설명합니다. 시험 담당자는 각 시험의 절차대로 레지스터를 쓰고 읽은 뒤, 기대 결과와 비교해 합격 여부를 판정합니다.

대상 독자는 EC FAN 펌웨어 개발자와 시험 담당자입니다. Modbus RTU의 기능 코드(FC)와 RS485 마스터 도구 사용법은 알고 있다고 가정합니다.

모든 기대값은 스펙이 아니라 **각 브랜치에 실제로 구현된 코드**를 기준으로 합니다. 코드가 스펙과 다르게 동작하는 부분은 각 시험의 비고에 적었습니다.

| 항목 | 기본값 | 관련 레지스터 |
|---|---|---|
| 노드 ID | 1 | D100 |

| 데이터 형식 | 8E1(데이터 8비트, 짝수 패리티, 정지 1비트) | D14A = `0x0000` |
| 응답 대기 시간 | 500 ms 이상 권장 | - |

### 2.4 펌웨어 준비

1. 시험할 브랜치를 체크아웃합니다. 개발 PC의 작업 트리에 커밋하지 않은 작업이 있으면 별도 워크트리를 만들어 체크아웃합니다.

   ```
   git worktree add ../ec-fan-test ebm/D15B-D15F_fail-safe
   ```

2. IAR EWARM으로 Main 프로젝트 `ECFAN-Main/EWARM/ECFAN-Main.ewp`를 빌드합니다. 플래시 대상이 Main+Inverter인 브랜치는 `ECFAN-Inverter/EWARM/INV_STM32G491CCT3.ewp`도 빌드합니다.
3. 평소 방법대로 펌웨어를 다운로드합니다.
4. 전원을 껐다 켜고, FC04 D002(Main 펌웨어 버전)와 D004(Inverter 펌웨어 버전)를 읽어 다운로드가 반영됐는지 확인합니다.

새 기능은 처음 부팅할 때 각자의 EEPROM 블록에 기본값을 기록합니다. 이 기록은 DC-link 전압이 190 V 이상일 때만 일어나므로, 첫 부팅은 정격 전원을 넣은 상태에서 합니다.

## 3. 공통 규칙

### 3.1 레지스터 접근 방법

| 레지스터 | 읽기 | 쓰기 | 표기 예 |
|---|---|---|---|
| Holding register | FC03 | FC06(1개), FC10(여러 개) | `FC06 D15C ← 0x0002` |
| Input register | FC04 | 쓸 수 없음 | `FC04 D028 ×1` |
| LSM 오브젝트(0x2000~0x4FFF) | FC 0x2B(MEI 0x0D) | FC 0x2B | `FC2B 0x4023` |

- 이 문서의 "D15C"는 Modbus 주소 `0xD15C`를 뜻합니다.
- Holding D012와 Input D012처럼 주소가 같아도 종류가 다른 레지스터가 있습니다. 절차에 적힌 FC03과 FC04를 반드시 구분합니다.

### 3.2 단일 레지스터 원칙

기준 펌웨어(`18b625e`)는 D 영역에서 여러 레지스터를 한 번에 읽거나 쓸 때 주소를 잘못 계산합니다. 이 결함은 `ebm/D380-D49F_modbus-addressing-mirror` 브랜치에서만 고쳐졌습니다. 따라서 다른 브랜치를 단독으로 시험할 때는 다음을 지킵니다.

- 쓰기는 FC06으로 한 레지스터씩 합니다. 절차에 FC10이 적힌 경우만 FC10을 씁니다.
- **기준 펌웨어의 FC10은 0x6000 이상 주소를 CiA402 오브젝트(0x603F 기준)로 해석합니다.** 그래서 D 영역에 FC10으로 쓰면 엉뚱한 오브젝트에 값이 들어갑니다. 예를 들어 D101에 쓴 값은 0x6040(Controlword)에 들어갑니다. 주소 매핑 브랜치가 아니면 절차에 없는 FC10을 D 영역에 쓰지 않습니다.
- LSM 오브젝트(0x2000~0x4FFF)는 FC 0x2B로만 접근합니다. 기준 펌웨어는 FC03이나 FC06으로 0x4009 같은 주소에 접근하면 오브젝트를 찾지 못해 NULL을 참조합니다.
- 오브젝트가 없는 D 주소는 읽지 않습니다. 기준 펌웨어는 이때도 NULL을 참조해 MCU가 멈출 수 있습니다. 주소 매핑 브랜치는 예외 `0x02`로 응답하도록 고쳤습니다.
- 읽기는 한 레지스터씩 하거나, 절차에 적힌 연속 구간만 한 번에 읽습니다.
- D160, D162 같은 32비트 레지스터는 주소 매핑 브랜치에서만 두 레지스터로 올바르게 읽힙니다.

### 3.3 저장 확인 방법

"전원 재투입 후 유지"를 확인하는 시험은 다음 순서를 따릅니다.

1. FC04 D013(DC-link 전압)이 190 이상인지 확인합니다. 190 미만이면 EEPROM에 저장되지 않습니다.
2. 값을 씁니다.
3. 1 s 이상 기다립니다.
4. 주전원을 끄고 10 s 뒤에 다시 켭니다.
5. 같은 레지스터를 읽어 쓴 값과 같은지 확인합니다.

### 3.4 시간 기준

펌웨어는 설정값 처리를 약 102 ms마다 하고, Inverter 상태는 약 500 ms마다 받아 옵니다. 운전 상태나 Input register 값을 확인하는 단계에서는 쓰기 후 1 s 이상 기다린 뒤 읽습니다. 절차에 다른 대기 시간이 적혀 있으면 그 값을 따릅니다.

### 3.5 예외 응답 판정

| 예외 코드 | 의미 | 이 펌웨어에서 나오는 경우 |
|---|---|---|
| `0x01` | 지원하지 않는 FC | 정의되지 않은 FC, 잘못된 서브 기능 |
| `0x02` | 잘못된 주소 | 구현되지 않은 주소, 쓰기 불가 영역 |
| `0x03` | 잘못된 값 | 레지스터 개수나 바이트 수 오류 |
| `0x04` | 처리 실패 | 범위 밖 값 거부, 권한 없음, 운전 중 거부 |

허용되지 않는 값을 쓰면 스펙은 `0x03`을 기대하지만, 이 펌웨어는 대부분 `0x04`로 응답합니다. 기존 서버 코드가 오브젝트의 쓰기 실패를 모두 `0x04`로 돌려주기 때문입니다. 각 시험의 기대 결과는 실제 응답 코드를 기준으로 적었습니다.

### 3.6 D011과 D012 비트표

Input D011(Motor status)과 Input D012(Warning)의 비트 위치는 스펙 3.9절과 3.10절 기준입니다.

| 비트 | D011 Motor status | D012 Warning |
|---|---|---|
| 15 | - | LRF(Shedding 동작 중) `0x8000` |
| 14 | - | UeHigh `0x4000` |
| 12 | UzLow(DC-link 저전압 에러) `0x1000` | UzHigh(DC-link 과전압) `0x1000` |
| 10 | RL_Cal(캘리브레이션 에러) `0x0400` | OpenCir(입력 단선) `0x0400` |
| 9 | - | n_Low(감시 속도 미만) `0x0200` |
| 8 | n_Limit(속도 한계 초과) `0x0100` | RL_Cal(캘리브레이션 중) `0x0100` |
| 7 | BLK(구속) `0x0080` | Braking `0x0080` |
| 6 | HLL(홀 센서 에러) `0x0040` | UzLow(DC-link 저전압) `0x0040` |
| 5 | TFM(모터 과열) `0x0020` | TEI_high(제어부 온도 높음) `0x0020` |
| 4 | FB(Fan Bad, 에러가 있으면 항상 1) `0x0010` | TM_high(모터 온도 높음) `0x0010` |
| 3 | SKF(MCU 간 통신 에러) `0x0008` | TE_high(출력단 온도 높음) `0x0008` |
| 2 | TFE(출력단 과열) `0x0004` | P_Limit(파워 리미터 동작) `0x0004` |
| 1 | - | L_high `0x0002` |
| 0 | PHA(전원 결상, 단상은 저전압) `0x0001` | I_Limit(전류 제한 동작) `0x0001` |

기준 펌웨어는 D012 비트 순서가 스펙과 반대입니다. 예를 들어 Inverter의 DC-link 저전압 경고가 bit6이 아니라 bit9에 나타납니다. 이 순서는 `ebm/D012-input_warning-bit-order-fix` 브랜치에서 고쳤습니다. 다른 브랜치를 단독으로 시험할 때는 다음과 같이 나타납니다. 각 시험의 기대 결과에는 이 차이를 반영했습니다.

- Inverter가 올리는 경고는 반대 위치에 나타납니다. 예를 들어 I_Limit는 `0x8000`입니다.
- Fail-safe(OpenCir `0x0400`), 모니터링(n_Low `0x0200`), Shedding(LRF `0x8000`), 로터 캘리브레이션(RL_Cal `0x0100`)이 직접 세우는 비트는 스펙 위치에 나타납니다.
- 파워 리미터의 P_Limit은 구조체 필드로 세우므로 단독 브랜치에서는 반대 위치(`0x2000`)에 나타나고, D012 순서 수정 후 `0x0004`가 됩니다.
- D012 순서를 바로잡으려면 Main과 Inverter를 모두 수정 브랜치로 올려야 합니다. Main은 Inverter의 경고값을 그대로 복사하기 때문입니다.

### 3.7 안전

- 운전 시험은 팬 날개에 보호망을 씌운 상태에서 합니다.
- 회전자 구속 시험(SHD)은 지그로 구속하고, 손으로 잡지 않습니다.
- 회전 방향 전환 시험은 팬이 정지한 뒤 반대 방향으로 재기동하는지 확인하는 시험입니다. 회전 중 강제 역전을 기대하지 않습니다.

## 4. 통신 계층 시험

### 4.1 D 영역 주소 매핑과 미러 레지스터 (`ebm/D380-D49F_modbus-addressing-mirror`)

이 브랜치는 D 영역 FC03, FC04, FC06, FC10을 레지스터 주소마다 따로 해석하도록 고쳤고, 미러 레지스터를 추가했습니다. 이 절의 시험에서만 FC10을 D 영역에 자유롭게 씁니다.

**준비물과 전제**

- 마스터는 Modbus Poll이나 QModMaster를 쓰고, FC 0x2B(ADR-08)는 시리얼 터미널로 아래 프레임을 그대로 보냅니다.
- Main에만 이 브랜치를 올리고 Inverter는 기준 이미지(`18b625e`)를 그대로 씁니다.
- 모터는 정지(D001 = 0), Ain1은 0 V로 둡니다. ADR-10에서 설정값 소스(D101)를 Ain1로 바꾸기 때문입니다.
- 첫 부팅 때 미러 테이블은 모두 0입니다. FC03 D480 ×32와 FC03 D400 ×16이 모두 `0x0000`인지 먼저 확인합니다.
- EEPROM 기본값일 때 D100 = `0x0001`, D101 = `0x0001`, D102 = `0x0000`, D106 = `0x0002`, D11F와 D120 = `0x1388`(5000)입니다. D12A~D12D, D15F, D160~D163은 RAM 값이라 부팅 시 `0x0000`입니다.
- 이 브랜치 단독 이미지에 있는 D 영역 오브젝트는 다음과 같습니다. 나머지 주소는 모두 미할당입니다.
  - Holding: D000, D001, D100~D102, D106, D119, D11F, D120, D12A~D12D, D137, D138, D13B, D147, D149, D14A, D15F, D160(32비트), D162(32비트), D1FF
  - Input: D000~D005, D010~D013, D015, D017, D019, D01B, D023~D026, D028, D02D, D050~D052
- 예외 응답 프레임은 다음과 같습니다.
  - FC03: `01 83 02 C0 F1`, FC04: `01 84 02 C2 C1`, FC06: `01 86 02 C3 A1`, FC10: `01 90 02 CD C1`
- FC 0x2B 프레임은 다음과 같습니다.


**단독 시험 한계**

- 다른 브랜치가 추가하는 레지스터(D103~D105 등)가 없어 ADR-02 ①은 단독에서 `0x02`입니다. 파라미터 세트 브랜치를 병합한 뒤에는 7개 값을 돌려줍니다.
- D380 쓰기가 원래 주소의 권한을 따르는지, D400과 D480을 고객 레벨 이상만 쓸 수 있는지는 비밀번호 브랜치를 병합한 뒤 시험합니다(8절 INT-08).
- ADR-09와 ADR-14의 "리셋 시 0" 판정은 D160이 RAM 값인 단독 이미지에서만 유효합니다. 병합 후에는 파라미터 세트 브랜치가 D160을 저장하므로 다른 RAM 표식을 골라야 합니다.
- FC 0x2B 경로는 이 브랜치의 주소 해석과 권한 검사를 거치지 않습니다.

### 4.2 비밀번호와 쓰기 권한 (`ebm/D002-D004_password-access`)

스펙은 쓰기 권한을 ebm-papst, 고객(customer), 최종 사용자(end customer) 세 레벨로 나눕니다. 이 펌웨어는 저장된 비밀번호가 0이면 그 레벨을 보호하지 않으므로, 공장 기본 상태에서는 모든 레지스터를 쓸 수 있습니다.

**준비물과 전제**

- 마스터는 Modbus Poll이나 QModMaster를 쓰고, FC 0x2B는 시리얼 터미널로 아래 프레임을 그대로 보냅니다. PW-08과 PW-09 동안에는 주기적으로 쓰기를 하는 마스터(LS 웹 GUI 등)를 떼고 읽기만 합니다.
- Main에만 이 브랜치를 올립니다. 모터는 정지 상태로 둡니다.
- **비밀번호 입력은 FC06으로 D002, D003, D004를 차례로 씁니다.** 이 브랜치 단독에서 FC10 D002 ×3을 보내면 기준 펌웨어의 FC10 결함 때문에 CiA402 오브젝트에 값이 들어가므로 쓰지 않습니다. FC10 D002 ×3은 주소 매핑 브랜치를 병합한 뒤에만 씁니다.
- D002가 상위 워드입니다. 시험용 비밀번호는 고객 `0x1111 0x2222 0x3333`, ebm-papst `0x0000 0x0000 0x5678`입니다.
- 시험 레지스터는 다음과 같습니다.
  - D12A: 최종 사용자 레벨, RAM 값
  - D15F: 고객 레벨, RAM 값, 부팅 시 0
  - D1FF: ebm-papst 레벨(종단 저항). FC03로 현재 값을 읽어 같은 값을 다시 씁니다
  - D013, D200: 쓰기 불가. Holding D012는 최종 사용자 레벨로 쓸 수 있지만, PW-13 ③처럼 D013까지 함께 쓰는 요청은 전체가 거부됩니다
- 비밀번호 변경은 LSM 오브젝트 0x4020~0x4023으로 합니다. 0x4020~0x4022에 새 비밀번호를 쓰고 0x4023에 대상 레벨(2 고객, 3 ebm-papst)을 쓰면 EEPROM에 저장됩니다. 0x4023을 읽으면 현재 레벨(1, 2, 3)이 나옵니다.
- 0x4009(access_password)는 RAM 값이라 부팅 시 0입니다.
- FC 0x2B 요청의 바이트 배치는 다음과 같습니다.

  | 오프셋 | 내용 |
  |---|---|
  | 0 | 노드 |
  | 1 | `0x2B` |
  | 2 | MEI `0x0D`(다른 값이면 `0x02`) |
  | 3 | 제어. 쓰기 `0x80`, 읽기 `0x00` |
  | 4, 5 | `00 00` |
  | 6, 7 | 인덱스(상위 바이트 먼저) |
  | 8 | 서브인덱스 `00` |
  | 9, 10 | `00 00` |
  | 11, 12 | 길이. 요청에서는 무시하고, 응답에는 바이트 수(`00 02`)가 들어감 |
  | 13, 14 | 데이터(상위 바이트 먼저). 쓰기에만 넣음 |
  | 마지막 2바이트 | CRC(하위 바이트 먼저) |

- 쓰기 성공 응답은 요청과 같은 프레임입니다. 0x4xxx 쓰기가 실패하면 원인과 관계없이 `01 AB 02 DE F1`, D 영역 권한이 부족하면 `01 AB 04 5E F3`입니다.

### 4.3 시리얼 번호 주소 지정 (`ebm/D00C_D1A2-D1AA_serial-addressing`)

시리얼 번호로 팬을 지정하는 명령(0x43, 0x44, 0x46, 0x50), 진단 명령(FC 0x08), D00C, 식별 레지스터(D1A2~D1AA)를 시험합니다. 일반 Modbus 도구는 이 명령의 프레임을 만들지 못하므로, 시리얼 터미널로 아래 원시 프레임을 그대로 송신합니다. 프레임의 마지막 2바이트는 CRC-16/Modbus이며 하위 바이트가 먼저입니다.

**준비물과 전제**

- 버스에는 팬 1대만 연결합니다. 와일드카드나 브로드캐스트 명령에 여러 팬이 동시에 응답하면 충돌합니다.
- SN-01부터 순서대로 실행합니다. 각 행은 앞 행이 끝난 상태를 전제로 합니다.
- 주전원을 넣어 DC-link 전압이 190 V 이상인 상태에서 시험합니다. D100 저장에 이 조건이 걸려 있습니다.
- ebm-papst 권한은 0x4009(access_password) = 2017일 때 주어집니다. 0x4009는 FC 0x2B로만 씁니다. 이 값은 RAM에만 있어 전원을 다시 넣으면 0이 됩니다.
  - 쓰기: `01 2B 0D 80 01 00 40 09 00 00 00 00 02 07 E1 2D 4A`(응답은 같은 프레임)
- 팬 타입 기대값은 모터 ID와 전압 등급으로 정해집니다. 표의 기대 프레임은 EEPROM 초기 기본값인 모터 ID 0x1000, 전압 등급 1("ECF-S550-400") 기준입니다.
  - 모터 ID 읽기: `01 2B 0D 00 01 00 20 00 00 00 00 00 02 F3 31`(0x1000이면 응답 `… 02 10 00 88 E4`)
  - 전압 등급 읽기: `01 2B 0D 00 01 00 27 0A 00 00 00 00 02 85 5B`(1이면 응답 `… 02 00 01 E2 AB`)
- LS 시리얼은 다음 순서로 준비합니다.
  1. `01 2B 0D 00 01 00 24 24 00 00 00 00 10 30 18`로 원래 0x2424 값(16바이트)을 읽어 기록해 둡니다.
  2. 비밀번호 2017을 넣고 SN-15의 7번 프레임으로 "SC6D00001"을 씁니다.
  3. 전원을 다시 넣어 비밀번호를 해제합니다.
  4. 이전에 이 시험을 한 보드라면 SN-16의 1번(D1A4 = 0)과 6번(D1A5 = 0)을 먼저 실행해 오버라이드를 지웁니다.
  5. 시험이 끝나면 원래 LS 시리얼로 복원합니다.

## 5. 운전 지령 시험

5절의 시험은 공통으로 다음 조건을 따릅니다.

- 쓰기는 FC06만 씁니다. 3.2절의 FC10 결함 때문입니다.
- 별도 언급이 없으면 운전 모드는 개루프(D106 = 2), 설정값 소스는 RS485(D101 = 1)입니다.
- 개루프에서 FC04 D051(토크 지령, 0.1 %) = ⌊cmd × 1000 / 65536⌋이고, cmd가 6554(10 %) 미만이면 정지합니다.
- 속도 모드(D106 = 0)에서 FC04 D050(속도 지령, rpm) = ⌊cmd × 최대 속도 / 64000⌋이고, 100 rpm 미만이면 정지합니다.
- 최대 속도 예시는 Sirocco(모터 ID 0x1000) 1800 rpm 기준입니다. Axial(0x2000)은 1700 rpm으로 다시 계산합니다.
- D050과 D051은 Inverter가 돌려준 값이라 약 0.5 s 늦게 바뀝니다. 쓰기 후 1 s 이상 기다렸다가 읽습니다.
- 기준 펌웨어는 Ain이나 PWM 소스일 때 D001을 입력값으로 덮어씁니다. 이 동작은 기존 결함이며 시험 결과에 함께 나타납니다.
- 모듈 온도(FC04 D015)가 95 °C 미만인 상태에서 시험합니다. 온도 디레이팅이 끼어들지 않게 하기 위해서입니다.

### 5.1 I/O 구성, Enable, 소스 전환 (`ebm/D158-D15A_D00F_D148_D16A-D16C_io-enable-source`)

ebm-papst의 I/O 1~3을 이 보드의 핀에 다음과 같이 대응시켰습니다. 하드웨어가 지원하지 않는 모드는 쓰기를 거부합니다.

| ebm I/O | 물리 핀 | 허용 값 | 기본값 |
|---|---|---|---|
| I/O 1(D158) | FG_OUT(PC6) | 5(타코 출력), 6(진단 출력) | 5 |
| I/O 2(D159) | Analog_I_IN(PB1) | 3(4-20 mA 입력) | 3 |
| I/O 3(D15A) | PWM_IN(PA8) | 0, 1(디지털 입력), 7, 8(PWM 입력) | 8 |

**준비물과 전제**

- 0-10 V 전압원(Ain1), 4-20 mA 전류원(Ain2), PWM 발생기(PWM_IN 단자에 연결, 정적 0 V와 10 V 출력과 단발 펄스 기능 필요), FG_OUT 측정용 오실로스코프나 주파수 카운터, 외부 풀업 저항(FG_OUT은 오픈 컬렉터)이 필요합니다.
- 거부된 쓰기는 예외 `0x04`로 응답합니다.
- 기준 펌웨어는 부팅 후 처음 D101이나 D102를 쓸 때 D001을 0으로 만듭니다. 시험을 시작할 때 D102에 현재 값을 한 번 써 둡니다.
- I/O 3 단자 입력단은 반전형입니다(단자 High일 때 PA8 Low). 시험에서 단자 High는 10 V, Low는 0 V로 둡니다. [확인 필요: PWM_IN 입력 임계 전압, 단자 개방 시 PA8 레벨]

### 5.2 Fail-safe (`ebm/D15B-D15F_fail-safe`)

**준비물과 전제**

- 장비와 통신 설정은 5.1절과 같습니다. RS485 시험 중에는 모든 마스터의 폴링을 완전히 멈춥니다. 통신이 없는 동안 회전수는 FG_OUT 주파수(1 펄스/회전, f = rpm / 60)로 측정합니다.
- D15B~D15F에 범위 밖 값을 쓰면 **예외 없이 정상 응답**하고, 값은 마지막 유효값으로 되돌립니다. 5.1절의 I/O 브랜치(예외 `0x04`)와 처리가 다릅니다.
- 단독 빌드의 D028 평상시 값은 기존 코드 그대로입니다(D101 = 0이면 D023 값, 1이면 `0x0000`, 2이면 D024 값, 3이면 D025 값). Fail-safe 동작 중에만 `0x00FF`이 됩니다.
- D012의 OpenCir은 스펙 위치인 `0x0400`(bit10)으로 세웁니다. D012의 나머지 비트는 Inverter 경고이며 기준 펌웨어의 반대 순서로 나타납니다.
- 단선 판정은 FC04 D023, D024 값으로 합니다. D15F 기본값 3277은 Ain1 약 0.50 V, Ain2 약 4.80 mA입니다. 해제 기준은 3277 + 655 = 3932(약 0.61 V, 4.96 mA)입니다.
- **주의:** D15C ≠ 0이고 D15D ≠ 0이면, 마스터 통신이 없을 때 D15E × 100 ms 뒤 팬이 스스로 기동합니다. 전원을 켠 직후에도 마찬가지입니다.

### 5.3 파라미터 세트와 센서 제어 (`ebm/D103-D10D_D12A-D13F_parameter-set-sensor-control`)

**준비물과 전제**

- 0-10 V 전압원, 4-20 mA 전류원, PWM 발생기(듀티 5~95 %만 유효), 시험용 팬이 필요합니다.
- 연속으로 읽어도 되는 구간은 D103~D10D, D12A~D12E, D13C~D13F, D164~D169입니다. 나머지는 하나씩 읽습니다.

### 5.4 모듈레이션과 속도 제한 (`ebm/D10E-D11A_D128_modulation-speed-limits`)

**준비물과 전제**

- 장비는 5.3절과 같습니다. D10E~D113과 D116~D11A는 연속이라 FC03로 한꺼번에 읽어도 됩니다.
- FC06 응답은 보정 전의 요청 값을 그대로 돌려줍니다. 실제 저장값은 반드시 FC03로 다시 읽어 확인합니다. 범위 밖 값에는 예외 없이 보정만 합니다.
- 모듈레이션 레지스터 m은 하위 바이트만 쓰고 256이 100 %입니다. 최소값은 m × 256, 최대값은 m × 256 + 255로 적용합니다.

### 6.1 파워 리미터와 온도 디레이팅 (`ebm/D12F-D16D_power-limiter`)

**준비물과 전제**

- Main에만 이 브랜치를 올립니다. D12F~D16D는 주소 사이에 빈칸이 있으므로 레지스터를 하나씩 읽습니다.
- 400 V급 DC-link(약 537 V), 날개를 단 시험용 팬, DC 측 전력계를 준비합니다. PWR-05에는 동력계가 필요합니다. D001, D051, D050, D013, D052, D015, D012를 100~200 ms 주기로 기록합니다.
- 파워 레지스터 1 LSB는 25.6 W입니다. 이 브랜치에는 D1A0, D1A1이 없어 기본값 12800을 쓰므로 기준 전력은 256 V × 25.6 A = 6553.6 W입니다.
- 리미터가 쓰는 측정 전력은 D013[V] × D052[0.1 A] / 10[W]이고, 시정수 0.8 s 필터를 거칩니다. D052가 0.1 A 단위라 537 V에서 측정 전력의 한 단계는 53.7 W입니다.
- 리미터는 제한값을 초당 최대 5 %(개루프 D051 기준 50/s)씩 바꿉니다. 하한은 15 %(D051 149, 속도 모드 276 rpm)입니다.
- 이 브랜치 단독에서는 D012 비트가 반대 순서라 P_Limit은 `0x2000`, Inverter I_Limit은 `0x8000`으로 읽힙니다.
- D106은 D001보다 먼저 씁니다. 모드가 바뀌면 D001이 0이 되기 때문입니다.

### 6.2 Shedding (`ebm/D150-D152_shedding`)

기동에 실패하면(날개가 얼어붙은 경우 등) 회전 방향을 번갈아 바꾸며 토크를 높여 다시 기동합니다. 정해진 횟수 안에 풀리지 않으면 "모터 구속"으로 래치합니다.

**준비물과 전제**

- 기본 조건은 개루프 D106 = `0x0002`, D001 = `0x4000`(D051 250, 25 %)입니다.

### 6.4 D012 경고 비트 순서 (`ebm/D012-input_warning-bit-order-fix`)

**준비물과 전제**

- 비교를 위해 Main과 Inverter를 모두 기준 펌웨어(`18b625e`)로 둔 상태의 결과를 먼저 기록합니다.
- Main은 Inverter의 경고값을 그대로 복사합니다. 따라서 Inverter 경고의 비트 위치는 Inverter 펌웨어가 정합니다. 두 MCU를 모두 올려야 위치가 맞습니다.

| P_Limit | `0x0004` | `0x2000` |

| TM_high | `0x0010` | `0x0800` |

## 7. 상태와 이력 시험

### 7.0 에러와 경고 유발 방법

7절의 시험은 아래 방법으로 에러와 경고를 일으킵니다. 조건은 Inverter 코드(`protect.c`) 기준입니다. 단독 브랜치에서는 D012 비트가 기준 펌웨어의 반대 위치로 나타납니다(3.6절).

| 이름 | 방법 | 결과 | 해제 |
|---|---|---|---|
| 유발-BLK(구속) | 정지 상태에서 지그로 회전자를 고정하고 D106 ← `0x0000`, D13B ← `0x03E8`, D001 ← `0x29AB`(300 rpm)를 씁니다 | 약 3 s 뒤 D011 = `0x0090`(BLK, FB) | Inverter가 1.5 s 뒤 스스로 해제합니다. BLK를 확인하면 바로 D001 ← `0x0000`을 씁니다. 지령이 최대 속도의 40 %(720 rpm) 이상이면 BLK보다 n_Limit가 먼저 날 수 있습니다 |
| 유발-NL(속도 편차) | D106 ← `0x0000`, D13B ← `0x0064`(10.0 %), D001 ← `0xFA00`을 씁니다. D02D가 100 rpm 이상인지 확인합니다 | 실제 속도가 지령보다 최대 속도의 40 % 넘게 낮으면 100 ms 뒤 D011 = `0x0110`(n_Limit, FB) | D001 ← `0x0000`. 편차가 사라지고 3 s 뒤 자동 해제됩니다. [확인 필요: 서보 OFF 상태에서도 자동 해제되는지. 안 되면 전원을 다시 넣습니다] |

- Inverter는 저속 경고도 UzLow 필드로 올립니다. 그래서 유발-US와 유발-UZ는 같은 비트에 나타나며, D012 순서 수정 후에는 둘 다 bit6(`0x0040`)에 나타납니다.
- TFE와 TFM은 과열이 필요해 안전하게 일으킬 방법이 없습니다. HLL과 SKF는 펌웨어가 만들지 않습니다. 이 네 가지는 시험하지 않습니다.
- 시험이 끝나면 D13B ← `0x03E8`, D106 ← `0x0002`로 되돌립니다. 두 값은 EEPROM에 저장되는 값입니다.

### 7.1 모니터링과 에러 이력 (`ebm/D009-D03D_D180-D1A1_monitoring-error-history`)

**준비물과 전제**

- 마스터의 스캔 주기는 100 ms 이하로 둡니다. 시험용 팬, 교류 전력계(Wh 적산 가능), 스톱워치, 회전자 구속 지그를 준비합니다. 400 V급이면 결상용 단극 스위치, 필요하면 가변 교류 전원도 준비합니다.
- 연속으로 읽어도 되는 구간은 D009~D00A, D184~D1A1(30개), FC04 D013~D014, D027~D02A입니다. 오브젝트가 없는 주소(D181, D183, Input D02B 등)는 읽지 않습니다.

- EEPROM 저장은 메인 루프(0.5 s 주기)에서 D013 ≥ 190일 때만 합니다.

### 7.2 릴레이 출력 (`ebm/D153_D620-D624_relay-output`)

**준비물과 전제**

- 릴레이 접점(COM~NO)에 도통 시험기를 연결합니다. 시간 측정은 풀업을 단 접점을 로거나 오실로스코프로 보는 방법을 권합니다. PA9 측정용 멀티미터, 스톱워치, 결상 스위치(400 V급), 구속 지그를 준비합니다.

### 7.3 로터 위치 센서 캘리브레이션 (`ebm/D1F7-D1F8_rotor-calibration`)

D1F8은 Inverter에 이미 있던 홀 센서 보정 시퀀스(servo_mode 0xF2)를 실행합니다. 시퀀스는 약 10 s 저속 회전과 약 26 s 정지 정렬로 이루어지며, 성공하면 Inverter가 결과를 플래시에 저장합니다.

**준비물과 전제**

- Main과 Inverter 모두 이 브랜치로 올립니다. Inverter 변경이 없으면 시퀀스 종료 판정이 달라집니다.
- 시험용 팬은 무부하로 날개가 자유롭게 돌게 둡니다. D013 ≥ 190을 확인합니다.
- 시작 상태: D101 = `0x0001`, D106 = `0x0002`, D001 = `0x0000`, Inverter 알람 없음(D011 = `0x0000`)
- 다음 레지스터를 0.5 s 주기로 계속 읽습니다: FC03 D1F8, FC04 D011, D012, D02D, D051(이번 캘리브레이션 전류 %)
- 판정 비트는 다음과 같습니다.
  - 실패: D011 = `0x0410`(RL_Cal bit10과 FB bit4)
  - 진행 중: D012 & `0x0100`(bit8)
  - 에러 리셋: Holding D000 ← `0x0004`
- 단계별 시간: 준비 1.2~10 s, 시작 확인 최대 5 s, 실행 15~90 s, 확인 1.2 s
- 정지 판정: Inverter 서보 OFF이고 D02D ≤ `0x0028`(40 rpm)
- D011과 D012 비트가 드물게 한 번 0으로 읽힐 수 있습니다. 연속 두 번 읽어 판정합니다.

- 스펙은 D1F7, D1F8 쓰기를 ebm-papst 레벨로 제한하지만 이 브랜치는 권한을 검사하지 않습니다. 비밀번호 브랜치를 병합한 뒤 다시 확인합니다.

### 7.4 공장 설정과 고객 설정 (`ebm/D005-D006_D170-D17F_D200-D2FF_factory-customer-setting`)

**준비물과 전제**

- Main에만 이 브랜치를 올립니다. D 영역 Holding 쓰기는 FC06만 씁니다. D2xx와 D7xx는 FC03로 최대 125개까지 한 번에 읽을 수 있습니다.
- D013 ≥ 190이고 모터 정지(D001 = `0x0000`) 상태에서 시험합니다. 부팅 후 2 s 이상 지난 뒤 시작합니다. 첫 Inverter 응답 전에는 DC-link 전압이 0으로 보여 D005와 D006이 에러가 됩니다.
- 주소 규칙: 고객 영역 = 원래 주소 + `0x100`(D11F는 D21F), 공장 영역 = 원래 주소 + `0x180`(D11F는 D29F). D600~D626은 D700, D780에 같은 규칙으로 대응합니다.
- 비트 정의
  - D005: bit0 공장 → 현재(`0x0001`), bit1 현재 → 공장(`0x0002`), bit2 에러(`0x0004`)
  - D006: bit0 고객 → 현재(`0x0001`), bit1 현재 → 고객(`0x0002`), bit2 에러(`0x0004`)
  - 명령 비트는 메인 루프(약 0.5 s 주기)가 복사를 끝낼 때까지 남아 있다가 `0x0000`이 됩니다. 실패하면 `0x0004`입니다. FC06 응답은 항상 정상입니다.
- 고객 영역 복사(D006)는 스펙 개요표에서 고객 쓰기 권한이 있는 파라미터만 대상으로 합니다. 이 브랜치 단독 이미지의 오브젝트 중에서는 D13B만 빠집니다.
- 비밀번호 브랜치가 없어 모든 명령이 허용됩니다.
- 예시 기준값(EEPROM 기본값 보드): D100 `0x0001`, D149 `0x0004`, D11F `0x1388`, D137 `0x0069`, D138 `0x005F`, D13B `0x2710`. 실제 값이 다르면 SET-01에서 기록한 값으로 바꿔 판정합니다.

## 8. 병합 후 통합 시험

브랜치를 하나로 병합한 펌웨어에서는 4~7절의 시험을 다시 수행하고, 아래 연동 항목을 추가로 확인합니다. 단독 시험에서는 다른 브랜치의 함수가 기본 동작(약한 정의)으로 대체되어 확인할 수 없었던 항목입니다.

| INT-08 | 비밀번호 + 주소 매핑 | 고객 비밀번호를 설정한 뒤 미러 레지스터 D380으로 보호된 주소에 씁니다 | 원래 주소 기준으로 권한 검사를 해서 거부합니다 |
| INT-09 | 비밀번호 + 시리얼 주소 지정 | ebm-papst 비밀번호를 0이 아닌 값으로 설정하고 입력한 상태에서 D1A2에 씁니다 | 0x4009 = 2017 없이도 쓰기가 허용됩니다. 비밀번호를 설정하지 않은 기본 상태에서는 지금처럼 2017이 필요합니다 |
| INT-10 | 비밀번호 + 공장·고객 설정 | 고객 레벨로 D005 bit1(D→F)을 씁니다 | ebm-papst 레벨이 아니므로 D005 bit2(Error)가 세워집니다 |
| INT-11 | D012 수정 + 릴레이 | DC-link 저전압 경고를 유발하고 D624 마스크를 bit6만 남깁니다 | 저전압 경고에서만 릴레이가 떨어집니다 |
| INT-12 | D012 수정 + 모니터링 | DC-link 저전압 경고와 D145 감시를 동시에 유발합니다 | UzLow는 bit6, n_Low는 bit9에 따로 나타납니다 |
| INT-13 | 로터 캘리브레이션 + I/O | 캘리브레이션 중 D00F = 0(Disable)을 씁니다 | [확인 필요: 병합 시 Disable 연동을 연결한 뒤 기대 동작 확정] |
| INT-14 | 전체 | Main 빌드의 `.map` 파일에서 코드와 상수 크기를 확인합니다 | 앱 영역 112 KB 이내 |
| INT-15 | 전체 | 기존 `OS 검증 리스트.md`의 2장(Modbus RTU), 3장(기본 동작), 4장(구동 동작)을 다시 수행합니다 | 기존 결과와 같습니다. 단, D13B 단위 변경과 온도 디레이팅 방식 변경은 7절과 6.1절 기준으로 판정합니다 |
