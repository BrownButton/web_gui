# 핸디로더 기반 ECFAN 제어 기능 정의 (보고용)

| 항목 | 내용 |
|---|---|
| 문서 목적 | 사내 핸디로더(유선 리모콘)로 ECFAN 드라이브를 제어·설정하기 위해 탑재할 기능 범위를 정의한다. |
| 검토 기준 | 현재 운영 중인 FanCM(PC용 Modbus RTU GUI)이 사용자에게 제공하는 기능을 전수 조사하고, 핸디로더의 21키 구성과 표시 장치 제약에 맞춰 선별하였다. |
| 작성일 | 2026-09-03 |
| 상세 근거 | `docs/handyloader-ecfan-feature-mapping.md` (레지스터 단위 대조표) |

---

## 1. 요약

- 핸디로더는 **운전 모니터, 운전 지령, 알람 처리, 기본 파라미터 설정, 장치 정보 조회**의 5개 영역을 기본 기능으로 탑재한다.
- **Motor ID 변경, 서보 튜닝, 공장 초기화**는 일반 사용자 오조작 방지를 위해 비밀번호 진입 방식의 **히든 기능**으로 분리한다.
- **펌웨어 다운로드, Chart, Terminal, 시뮬레이터, 다중 디바이스 일괄 제어**는 핸디로더의 역할과 하드웨어 규모를 벗어나므로 **탑재하지 않는다.**
- 기본 기능은 FanCM에서 이미 검증된 레지스터와 동작 방식을 그대로 사용하므로, 드라이브 펌웨어 추가 개발 없이 구현 가능하다. 단, 핸디로더 펌웨어에는 표준 Modbus 기능 코드 외에 FC 0x2B(LSM 전용) 구현이 필요하다.

---

## 2. 검토 배경 및 방법

FanCM은 Dashboard, Configuration, Information, Parameters, Update, Chart, Terminal 등 7개 화면으로 구성되어 있으며, 각 화면의 사용자 조작 항목을 드라이브 레지스터 단위로 정리하였다. 이후 아래 세 가지 관점으로 핸디로더 탑재 여부를 판단하였다.

1. **현장 사용 목적에 부합하는가**: 설치·시운전·유지보수 시 PC 없이 수행해야 하는 작업인지
2. **핸디로더 하드웨어로 구현 가능한가**: 21키 입력, 소형 표시부, 제한된 메모리와 통신 처리 능력
3. **오조작 위험이 있는가**: 일반 사용자에게 노출할 경우 장비 손상이나 설정 유실로 이어질 수 있는지

## 3. 기능 구성

### 3-1. 기본 기능 (일반 사용자 노출)

| 영역 | 기능 | 드라이브 레지스터 | 비고 |
|---|---|---|---|
| 운전 모니터 | 실제 속도 표시 | 0xD02D | 초기 화면 |
| | 운전 상태 표시 (정지·운전·이상) | 0xD011 | Motor status 비트 디코딩 |
| | 알람 코드 표시 | 0x603F | 이상 발생 시 코드와 명칭 표시 |
| | 경고 표시 | 0xD012 | 저전압·과열·제한 등 8종 |
| | 보조 계측값 (DC-link 전압, 모듈 온도, 모터 전류, 지령 속도) | 0xD013, 0xD015, 0xD052, 0xD050 | UP/DOWN으로 순환 |
| 운전 지령 | Setpoint 입력 및 적용 | 0xD001 | RPM 또는 % 단위, 숫자키 입력 |
| | RUN / STOP | 0xD001 | STOP은 Setpoint 0 쓰기 (FanCM과 동일) |
| | Setpoint 스텝 증감 | 0xD001 | UP/DOWN 키 |
| 알람 처리 | 알람 리셋 | 0x800E | RESET 키 |
| | 소프트웨어 리셋 | 0xD000 | 확인 절차 후 실행 |
| 기본 설정 | 동작 모드 (Speed / Open-loop) | 0xD106 | |
| | Setpoint 입력 소스 (AIN1 / RS485 / AIN2 / PWM) | 0xD101 | |
| | 회전 방향 (CW / CCW) | 0xD102 | |
| | 최대 속도 | 0xD119 | Setpoint 환산 기준값 |
| | 가속 시간 / 감속 시간 | 0xD11F / 0xD120 | |
| | 최대 코일 전류 | 0xD13B | |
| | 온도 디레이팅 시작점 / 종료점 | 0xD137 / 0xD138 | |
| | 센서 지령 소스, 센서 최솟값 / 최댓값 | 0xD147, 0xD160 / 0xD162 | |
| | 입력 커브 포인트 1·2 (X, Y) | 0xD12A ~ 0xD12D | AIN / PWM 현장 튜닝 |
| 통신 설정 | Fan Address (Slave ID) | 0xD100 | 변경 시 핸디로더 대상 ID 자동 추종 |
| | Baudrate / Parity | 0xD149 / 0xD14A | 드라이브 재시작 후 적용 |
| | 종단 저항 | 0xD1FF | |
| 장치 정보 | 시리얼 번호 | 0x2424 | 읽기 전용 |
| | MCU / Inverter 부트로더·펌웨어 버전 | 0x27F0 ~ 0x27F3 | 읽기 전용 |
| | 하드웨어 리비전, 전압 클래스 | 0x2709, 0x270A | 읽기 전용 |
| 파라미터 직접 접근 | 임의 주소 읽기 / 쓰기 | Holding / Input 전 영역 | SHIFT + 숫자키로 16진수 주소 입력 |
| 설정 복사 | HANDY ↔ DRIVE 파라미터 복사 | 상기 설정 항목 일괄 | 동일 설정을 여러 드라이브에 복제 |

### 3-2. 히든 기능 (비밀번호 진입)

| 기능 | 드라이브 레지스터 | 분리 사유 |
|---|---|---|
| Motor ID 변경 | 0x2000 (FC 0x2B) | 모터 교체 시에만 필요. 잘못 설정하면 구동 불가 |
| 제품 전압 클래스 변경 | 0x270A (FC 0x2B) | 200V / 400V 전환. Motor ID와 같은 메뉴에 배치 |
| 서보 튜닝 (관성비, P 게인, 적분 시상수, 토크 지령 필터, CW/CCW 토크 제한, 제어 입력 할당) | 0x2100 ~ 0x2104, 0x2111 / 0x2112, 0x211F / 0x2120 (FC 0x2B) | 개발·서비스 전용. 일반 사용자 조정 시 진동·과전류 위험 |
| 공장 초기화 | 0x1011 (FC 0x2B) | 전체 설정 유실. 비밀번호 진입 후 2단 확인 |

추가 검토 대상: 알람 항목별 활성/비활성(마스크), Auto Calibration. 두 항목은 FanCM에서도 별도 탭 또는 비밀번호 보호로 운영 중이므로, 필요 시 동일한 히든 메뉴에 편입한다.

### 3-3. 제외 기능 (탑재하지 않음)

| 기능 | 제외 사유 |
|---|---|
| 펌웨어 다운로드 | 이미지 저장·전송·재시도 처리가 핸디로더 규모를 초과. PC(FanCM)에서 수행 |
| Chart (연속 스트리밍, 트리거, 주파수 응답) | 고속 데이터 수신과 그래프 표시 불가 |
| Terminal (수동 프레임 송수신) | 개발자 전용 도구 |
| 시뮬레이터 | PC 전용 |
| 다중 디바이스 일괄 제어 | 핸디로더는 단일 드라이브 대상 원칙. 멀티드롭 환경에서는 대상 ID 선택으로 대체 |

## 4. 키 배치 (21키)

핸디로더 키 각인은 서보 드라이브 기준이므로, ECFAN 용도로 아래와 같이 기능을 재정의한다.

| 키 | ECFAN 기능 |
|---|---|
| POSITION RUN | RUN / STOP 토글 |
| SELECT / DATA | 주소 입력 ↔ 값 입력 전환, 메뉴 항목 진입 |
| HOME | 초기 모니터 화면 복귀 |
| ESC | 취소, 상위 메뉴 |
| RESET | 알람 리셋. SHIFT + RESET은 소프트웨어 리셋 |
| FIND ADJUST | ECFAN 직접 대응 기능 없음. 후보: 파라미터 주소 검색, RPM / % 전환 (추후 확정) |
| 0 ~ 9 | 숫자 입력 |
| SHIFT + 4 ~ 9 | 16진수 A ~ F 입력 (주소 입력용) |
| SHIFT | 보조 키 (리셋 종류 전환, 큰 스텝 증감, 히든 메뉴 진입) |
| UP / DOWN | 메뉴 이동, 값 증감, 모니터 화면에서 Setpoint 스텝 증감 |
| HANDY ↔ DRIVE | 파라미터 복사 방향 선택 (DRIVE→HANDY 저장 / HANDY→DRIVE 복원) |
| WRITE | 입력값 확정 및 드라이브 쓰기 |

## 5. 메뉴 구성

| 메뉴 | 내용 |
|---|---|
| MON (모니터) | 실제 속도, 운전 상태, 알람 코드, 경고, 보조 계측값 |
| RUN (운전) | Setpoint 입력, RUN / STOP, 현재 단위(RPM / %) 표시 |
| PAR (설정) | 모터 제어, 보호, 센서 입력, 통신 설정, 파라미터 직접 접근 |
| ALM (알람) | 현재 알람 코드 및 명칭, 알람 리셋 |
| INF (정보) | 시리얼 번호, 펌웨어 버전, 하드웨어 리비전, 전압 클래스 |
| SYS (시스템) | HANDY ↔ DRIVE 복사, 소프트웨어 리셋 |
| 히든 메뉴 | SYS 화면에서 SHIFT + SELECT/DATA 길게 누름 → 비밀번호 입력 → Motor ID, 전압 클래스, 서보 튜닝, 공장 초기화. 일정 시간 무입력 시 자동 이탈 |

## 6. 추진 시 확인 및 결정 필요 사항

| # | 항목 | 내용 | 담당 (안) |
|---|---|---|---|
| 1 | 마스터 배타성 | RS-485 버스에 PC와 핸디로더를 동시에 연결하면 충돌한다. 핸디로더 사용 시 PC 분리 운용을 전제로 할지, 드라이브에 별도 포트를 둘지 결정 필요 | 기구 / 펌웨어 |
| 2 | Setpoint 입력 소스 | 핸디로더 운전 지령은 입력 소스가 RS485(0xD101 = 1)일 때만 유효하다. AIN / PWM 현장에서 핸디로더가 자동으로 소스를 전환할지, 모니터·설정 전용으로 둘지 결정 필요 | 기획 |
| 3 | FC 0x2B 구현 | 알람 코드, 시리얼, 펌웨어 버전, 히든 기능 전체가 FC 0x2B 경로다. 핸디로더 펌웨어에 해당 기능 코드 추가 필요 | 핸디로더 펌웨어 |
| 4 | Setpoint 환산 | Speed 모드는 `RPM ÷ 최대속도 × 64000`, Open-loop는 `% ÷ 100 × 65535`로 환산한다. 최대속도(0xD119)를 부팅 시 읽어 사용해야 FanCM과 표시값이 일치한다 | 핸디로더 펌웨어 |
| 5 | 자체 확장 레지스터 | 알람 리셋 0x800E, 모터 전류 0xD052, 지령 속도 0xD050은 ebm-papst 표준 스펙 외 자체 정의 주소다. 사양서 반영 전 드라이브 펌웨어 팀과 주소 확정 필요 | 드라이브 펌웨어 |
| 6 | 통신 설정 변경 후 재접속 | Baudrate / Parity 변경은 드라이브 재시작 후 적용되므로, 핸디로더가 새 설정으로 자동 재접속하는 절차 필요 | 핸디로더 펌웨어 |
| 7 | FIND ADJUST 키 용도 | ECFAN에 직접 대응 기능이 없어 용도 확정 필요 | 기획 |
| 8 | 알람 이력 | 핸디로더 ALM 메뉴에 알람 이력(0xD184 ~ 0xD19F)이 유용하나 FanCM과 드라이브 모두 미구현 상태. 지원 여부 확인 후 추가 검토 | 드라이브 펌웨어 |

## 7. 결론

핸디로더에는 FanCM Dashboard·Configuration·Information 화면의 사용자 기능을 중심으로 **기본 기능 5개 영역**을 탑재하고, 설정 유실이나 구동 불가로 이어질 수 있는 **Motor ID 변경·서보 튜닝·공장 초기화는 히든 기능**으로 분리한다. PC 환경이 필요한 **펌웨어 다운로드·Chart·Terminal·시뮬레이터·다중 디바이스 일괄 제어는 탑재하지 않는다.** 기본 기능은 FanCM에서 검증된 레지스터와 동작 방식을 그대로 사용하므로 드라이브 측 추가 개발 부담이 없으며, 6절의 확인 사항이 정리되면 핸디로더 펌웨어 사양서 작성 단계로 진행할 수 있다.
